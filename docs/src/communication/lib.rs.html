3//! # Naming convention
4//!
5//! - **`_zc` suffix**: zero-copy methods for types implementing [`ZeroCopy`].
6//!   Bypass `ark_serialize` entirely and transmute slices to/from raw
7//!   bytes.  On little-endian platforms this is a pointer cast –
8//!   zero allocation, zero per-element work.
9//!   Supported types: `RingElement<T>`, `Rep3RingShare<T>`.
10//!
11//! - **No suffix** (default): generic serialized methods via
12//!   `CanonicalSerialize` / `CanonicalDeserialize`.  Use these for
13//!   types that need actual serialization (seeds, tuples, arrays, etc.).
14//!   Optimized: uses `size_of::<F>()` heuristic capacity to avoid
15//!   the O(N) `serialized_size()` traversal.
16//!
17//! - **`_fast` suffix**: specialized serialized methods for **fixed-size**
18//!   `CanonicalSerialize` types.  Computes exact buffer size from a
19//!   single element's `serialized_size()`, then writes the length
20//!   prefix + per-element data in one pass.  Zero Vec reallocation
21//!   guaranteed.
22//!
23//! # Performance hierarchy (fastest → slowest)
24//!
25//! 1. `_zc` — zero-copy pointer cast, ~0 overhead
26//! 2. `_fast` — exact allocation, 1-pass serialization
27//! 3. default (no suffix) — heuristic allocation, ark serialization
